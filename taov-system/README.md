# תאוב — מערכת עסקית מקומית בעברית

הפיתוח נשמר בענף `taov-system` בלבד. אתר אבירית המקורי ו־main אינם משתנים. גרסה מקומית עם SQLite; נתונים סינתטיים בלבד. אין מנגנון לשליחת הודעות אמיתיות, בקשות חתימה או כתיבה ל־Google.

## התקנה והפעלה ב־Windows

1. התקינו **Node.js 24 LTS עדכני (24.5 ומעלה)** מאתר https://nodejs.org.
2. הורידו ZIP מענף `taov-system` ב־GitHub באמצעות **Code → Download ZIP**, או שכפלו:

```powershell
git clone --branch taov-system https://github.com/dudid464/dudid.git
cd dudid\taov-system
```

3. אם הורדתם ZIP: חלצו הכול ופתחו PowerShell בתיקיית `taov-system` שבתוך תיקיית המאגר.
4. הריצו:

```powershell
npm ci
npm test
npm start
```

5. פתחו במחשב שלכם `http://127.0.0.1:3000`. משתמש: `admin`. הסיסמה הראשונית האקראית מופיעה במסוף פעם אחת; שמרו אותה במנהל סיסמאות. שנו אותה במסך „שינוי הסיסמה שלי”. שינוי סיסמה מנתק את החיבור ומחייב כניסה מחדש.
6. עצירה: Ctrl+C. הפעלה חוזרת: `npm start`. הנתונים נשארים ב־`data/taov.sqlite`; אין למחוק את `data`.

אפשר להגדיר `ADMIN_PASSWORD` לפני יצירת המסד הראשונה בלבד. אסור לשמור סיסמאות בקוד, ב־Git או בצילומי מסך. Windows לא הורץ בפועל; בדיקות המערכת בוצעו ב־Linux וב־Docker עם Node 24.

## ניהול משתמשים והרשאות

מנהל יכול להוסיף משתמש, לשנות תפקיד, לאפס סיסמה, להשבית ולהפעיל מחדש. כל שינוי תפקיד, איפוס או השבתה מנתק את כל חיבורי המשתמש. לא ניתן להשבית או להוריד הרשאות למנהל הפעיל האחרון. סיסמה: 12–256 תווים; שם משתמש: 3–40 תווי אנגלית, מספרים, מקף או קו תחתון. סיסמאות נשמרות בגיבוב scrypt עם salt נפרד; לא בהיסטוריה או ב־Git. איפוס נעשה ידנית בידי מנהל ללא הודעת דוא״ל או WhatsApp.

- **admin**: רשומות, משתמשים, ייבוא, היסטוריה וגיבויים.
- **editor**: קריאת ועריכת רשומות, טיוטות חתימה, בקרה מדומה ודוחות. ללא ניהול משתמשים, ייבוא או גיבויים.
- **viewer**: קריאה, דוחות וחיפוש; ללא שינוי נתונים. כל משתמש יכול לשנות את סיסמתו עם הסיסמה הנוכחית.

ההרשאות כלל־מערכתיות, ולא לפי תיק. אין מחיקת משתמשים; משתמש מושבת נשמר בהיסטוריה.

## ניהול העסק ולוח הבקרה

לידים, משפחות, עובדים, התאמות, תיקים, משימות ומסמכים: יצירה, עריכה, סטטוס, אחראי ומועד יעד. מזהים מוצגים בטבלה לקישור משפחה/עובד/תיק; השרת בודק שהרשומה המקושרת קיימת. מסמכים מצורפים עד 400KB, ללא הרצת תוכנם. הצעות התאמה מבוססות כישורים מופרדים בפסיקים ומציגות ציון; נדרשת בדיקה אנושית.

לוח הבקרה מציג:

- לידים פתוחים והתאמות בתהליך: כל מצב למעט „הושלם”, „נסגר” ו„בוטל”.
- משימות באיחור: מועד יעד מוקדם מהיום בשעון ישראל וסטטוס פתוח.
- הכנסות צפויות: סכום שדה „הכנסה צפויה” בתיקים פתוחים בלבד, בשקלים. ערך חסר הוא אפס. החישוב נעשה באגורות; אינו חשבונאות או הכנסה שהתקבלה.

„דוח PDF בעברית” מוריד PDF עם גופן עברי מוטמע ורישיון מצורף ב־`assets/FONT-LICENSE.txt`. יש גם דוח JSON וייצוא רשומות CSV. העוזר המקומי מבצע חיפוש מבוסס כללים, למשל „משימות פתוחות באיחור”; אין מודל AI או הבנת שפה כללית.

## חתימות והתראות — טיוטות וסימולציה בלבד

במסך „טיוטות חתימה לחוזים” בוחרים מסמך ושם חותם סינתטי. נשמרת טיוטה עם מזהה המסמך, גרסה וגיבוב SHA-256. שינוי המסמך לאחר מכן אינו משנה את גיבוב הטיוטה. הטיוטה אינה חתימה דיגיטלית, ואינה הוכחת זהות או חתימה משפטית. אין כפתור או API לשליחה או לחתימה אמיתית.

הבקרה פועלת אחת לדקה כשהשרת פועל ויוצרת התראת סימולציה על איחור במשימה או בתיק. היא אינה יוצרת כפילות של התראה פתוחה לאותה רשומה. אין חיבור WhatsApp או משלוח חיצוני.

## ייבוא — „דיל 2023 – תאוב”

המסך מיועד למנהל. יש לעבוד על **עותק סינתטי בלבד** של הגיליון; הקובץ המקורי והמבנה המדויק שלו לא סופקו ולכן אין הנחה קשיחה על כותרות או שם לשונית.

1. מאשרים שהנתונים סינתטיים.
2. טוענים קובץ **CSV בקידוד UTF-8** (פסיק או נקודה־פסיק) או **XLSX**, עד 500KB, ‏2000 שורות נתונים ו־40 עמודות. לקובץ Excel ניתן לבחור לשונית לפי שמה; שמות הלשוניות מוצגים לאחר הטעינה. XLS ישן דורש המרה ל־XLSX. נוסחאות נדחות — יש לשמור ערכים בלבד. שורת הכותרות חייבת להיות מלאה וייחודית.
3. בוחרים סוג רשומות וממפים עמודות. כותרות כגון שם, שם משפחה, אחראי, סטטוס, מועד יעד, סכום והערות מזוהות כהצעה בלבד. ניתן לתקן את כל המיפוי. תאריך נדרש כ־YYYY-MM-DD; תאריכי Excel רגילים מומרים אוטומטית. סטטוסים: חדש / בטיפול / ממתין / הושלם / נסגר / בוטל.
4. לוחצים „תצוגה מקדימה לפני שמירה”. מוצגים עד 20 פריטים ממופים, שגיאות לפי שורה ואזהרות על שמות כפולים. שגיאה מונעת שמירה של כל הייבוא.
5. מאשרים שמירה. רק כעת נוצרים הנתונים **במסד המקומי**. אין דריסה או עדכון של רשומות קיימות; שמות כפולים יוצרים רשומות נפרדות. שמירת כל האצווה היא עסקה אחת — כישלון מבטל את כולה. ניסיון לשמור שוב אותה תצוגה נדחה.

התצוגה הראשונית מציגה עד 10 שורות; שאר השורות נשמרות זמנית בזיכרון לצורך מיפוי. התצוגה פגה אחרי 15 דקות, ניתוק/כניסה מחדש או אתחול. לייבוא יש תקרת תצוגות מקדימות בזיכרון.

### Google Sheets — קריאה בלבד

באותו מסך מזינים Spreadsheet ID של עותק סינתטי וטווח, למשל `A1:AN2001` או `'שם לשונית'!A1:F100`. שם הקובץ ב־Drive אינו בהכרח שם הלשונית; אפשר לציין את הלשונית הנכונה בטווח. הקריאה מחזירה תצוגה וממשיכה לאותו תהליך מיפוי ואישור.

נדרש משתנה שרת `GOOGLE_ACCESS_TOKEN` עם גישה לגיליון ו־scope ‏`https://www.googleapis.com/auth/spreadsheets.readonly`. אין OAuth או רענון אסימון אוטומטי. בענן נדרשת הרשאת רשת ל־`sheets.googleapis.com`. `npm start` משתמש בתמיכת הפרוקסי הרשמית של Node, ושומר אימות TLS. בסביבת פרוקסי יש לספק גם את שרשרת האמון המקובלת, למשל `NODE_EXTRA_CA_CERTS`, בלי לבטל אימות.

כל בקשות Google הן GET בלבד. אין כתיבה לגיליון או סנכרון דו־כיווני. האסימון אינו מועבר לדפדפן ואינו נכלל בגיבוי. החיבור נבדק עם mock סינתטי שמוודא GET; לא בוצעה קריאה חיה ל־Google.

## גיבוי יומי מוצפן ושחזור

באתחול, ובבדיקה אחת לדקה, נוצר גיבוי יחיד לכל תאריך לפי **Asia/Jerusalem**, אם אינו קיים. אין תזמון כאשר המחשב או השרת כבויים; בהפעלה הבאה נוצר גיבוי ליום הנוכחי. גיבוי קיים מאומת ולא נדרס. נשמרים 14 גיבויים אחרונים כברירת מחדל (`BACKUP_RETENTION_DAYS`, בין 2 ל־365). הקבצים נמצאים ב־`data/backups`. שגיאת גיבוי מוצגת במסך הגיבוי ונרשמת הודעת כשל במסוף ללא סודות.

גיבוי יומי גרסה 2 כולל רשומות, מסמכים, היסטוריה, חשבונות מגובבים, הרשאות ומצבי השבתה. ההצפנה היא AES-256-GCM, עם salt ו־nonce אקראיים ומפתח הנגזר ב־scrypt.

- אפשר להגדיר `BACKUP_PASSPHRASE` בשרת (לפחות 20 תווים) ולשמור בניהול סודות. מפתח זה אינו ניתן להורדה מהמסך.
- אם לא הוגדר, נוצר מפתח אקראי פעם אחת ב־`data/backup.key` עם הרשאות קובץ מצומצמות. מנהל יכול להוריד אותו במסך „גיבוי יומי אוטומטי” לאחר אישור מפורש.
- **שמרו מפתח ועותק גיבוי מוצפן במקומות מאובטחים נפרדים, מחוץ למחשב.** מפתח ליד הגיבוי באותו דיסק אינו מגן מפני השתלטות על המחשב. בלי המפתח אין שחזור. Git ו־ZIP של הקוד אינם גיבוי לנתוני העבודה.
- אין להחליף מפתח בלי לשמור את המפתח הישן לגיבויים ישנים. הורדה אינה שולחת את המפתח לגורם חיצוני.

„שחזור מגיבוי” בממשק תומך בגרסאות 1 ו־2, וממזג **רשומות בלבד**: מזהים קיימים נשמרים, וחשבונות והיסטוריה קיימים אינם מוחלפים. הגיבוי הידני עם סיסמה נפרדת נשאר זמין בגרסה 1 ואינו כולל חשבונות.

לשחזור מלא מגיבוי יומי, כולל חשבונות והיסטוריה, לתיקייה **חדשה שאינה קיימת**:

```powershell
npm run recover -- "C:\Backups\taov-2030-01-03.enc.json" "C:\Keys\taov-backup-recovery-key.txt" ".\recovered-data"
$env:DATA_DIR = "$PWD\recovered-data"
npm start
```

כלי השחזור מסרב לתיקייה קיימת, כך שאינו דורס התקנה קיימת. הסיסמאות וההרשאות הן אלו שהיו בגיבוי. כשהוגדר מפתח בסביבת השרת במקום מפתח מקומי, יש להכין קובץ מפתח שחזור באופן מאובטח מחוץ ל־Git. אין להעלות אותו לצ׳אט.

## Docker

נדרשים Docker Desktop עם Linux containers ו־Compose. מתוך תיקיית היישום:

```powershell
docker compose up --build -d
docker compose logs taov
```

הסיסמה הראשונית נמצאת בלוג הראשון. היישום זמין במחשב המקומי ב־`http://127.0.0.1:3000`. הנתונים, הגיבויים והמפתח נשמרים ב־volume בשם `taov-data`; עצירה: `docker compose down`. **אין להשתמש ב־`down -v`**, שמוחק את הנתונים. הקונטיינר פועל כמשתמש ללא root וכולל healthcheck.

לבנייה בסביבת הענן עם CA של פרוקסי:

```bash
docker build --secret id=proxy_ca,src="$CODEX_PROXY_CERT" -t taov-system:local .
docker run --rm taov-system:local npm test
```

תעודת ה־CA ממופה זמנית לשלב ההתקנה ואינה מועתקת לשכבות. לחיבור Google בזמן ריצה בענן יש למפות CA לקריאה בלבד ולהגדיר `NODE_EXTRA_CA_CERTS` עם הפרוקסי המוגדר; אין לבטל TLS. בבדיקות Docker אין שימוש ברשת חיצונית של האפליקציה.

## בדיקות ומגבלות

- `npm test`: ‏19 בדיקות שרת/מודולים עם נתונים זמניים, כולל הרשאות, השבתה וסיסמאות, מדדים, PDF, חתימות מדומות, CSV/Excel, Google מדומה, עסקת ייבוא, הצפנה ושחזור.
- `npm run check`: תחביר שרת. `npm audit`: בדיקת תלויות. נדרש override ל־uuid ‏11.1.1 ומעלה עבור תלות ExcelJS; נשמר ב־lockfile ונבדק בייבוא/ייצוא Excel.
- `python3 test/browser_smoke.py`: בדיקת דפדפן מורחבת. דורשת Python עם Playwright ו־Chromium בנתיב Linux המוגדר בקובץ. כוללת מסכים חדשים, PDF, חתימה, משתמשים, ייבוא, הורדת מפתח, רוחב מובייל ויציאה.
- `python3 test/docker_smoke.py`: בדיקת Docker מקומית עם volume סינתטי זמני, התחברות, PDF ושמירה אחרי הפעלה מחדש. דורשת image ‏`taov-system:local` בנוי ו־Python; מנקה רק משאבים שהיא יוצרת.

אין שירות תצוגה ציבורי מובנה. שרת localhost בענן אינו קישור למחשב האישי. נדרשים תמיכת preview של סביבת האירוח או פריסה מאושרת כדי ליצור קישור מרוחק.

המערכת מיועדת כרגע לפיתוח מקומי עם נתונים סינתטיים. SQLite אינו מוצפן בדיסק; יש הרשאות כלל־מערכתיות, חיבורים בזיכרון, וללא OAuth, SSO, אימות דו־שלבי או חתימה משפטית. להפעלה מרוחקת נדרשים TLS, ‏`COOKIE_SECURE=1`, ניהול סודות, אחסון וגיבויים מחוץ למחשב ובדיקת הרשאות מתאימה. אין למחוק רשומות עסקיות; יש לסמן כהושלם. אין פרסום אוטומטי.

## שמירה ב־Git

כל שלב נשמר עם commit ו־push לענף `taov-system`. תיקיית `data`, סודות ותלויות מקומיות מוחרגים. אחרי שינוי קוד:

```powershell
git add taov-system
git commit -m "Describe the change"
git push origin taov-system
```

יצירת PR דורשת גישת GitHub API ל־`api.github.com` והרשאה מתאימה. push דרך Git ויצירת PR הן הרשאות נפרדות.
